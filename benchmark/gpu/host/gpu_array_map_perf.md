# BPF_MAP_TYPE_GPU_ARRAY_MAP perf (host-side)

This benchmark measures the **CPU-side** `BPF_MAP_TYPE_GPU_ARRAY_MAP` access path implemented by `nv_gpu_shared_array_map_impl`, i.e. `elem_update()` / `elem_lookup()` using CUDA Driver API `cuMemcpyHtoD/cuMemcpyDtoH`.

It is the path intended to be accelerated by a future `gdrcopy` integration.

## Setup

Tested on:

- GPU: NVIDIA GeForce RTX 5090 (PCI `00000000:02:00.0`)
- Driver: `575.57.08` (reports CUDA `12.9` in `nvidia-smi`)
- Kernel: `Linux 6.15.11-061511-generic`
- CUDA attribute: `CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED=0` (so GDRCopy pinning is not supported on this GPU)
- bpftime commit: `7ec6a54f8300a833a8df3e47cac851873da933dd`
- Build config: `BPFTIME_ENABLE_CUDA_ATTACH=ON`, `BPFTIME_CUDA_ROOT=/usr/local/cuda-12.9`

You can confirm the RDMA support bit with:

```bash
cat > /tmp/cuda_rdma_check.cpp <<'EOF'
#include <cuda.h>
#include <cstdio>
int main() {
  cuInit(0);
  CUdevice dev;
  cuDeviceGet(&dev, 0);
  int v = -1;
  cuDeviceGetAttribute(&v, CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED, dev);
  std::printf("CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED=%d\n", v);
}
EOF
g++ /tmp/cuda_rdma_check.cpp -I/usr/local/cuda-12.9/include -L/usr/local/cuda-12.9/lib64 -lcuda -o /tmp/cuda_rdma_check
/tmp/cuda_rdma_check
```

## GDRCopy install (optional)

If your GPU supports `CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED=1`, you can install GDRCopy and enable the bpftime fast-path:

```bash
git clone https://github.com/NVIDIA/gdrcopy /tmp/gdrcopy
cd /tmp/gdrcopy
make -j CUDA=/usr/local/cuda-12.9 prefix=/usr/local lib_install
sudo ldconfig
```

Build and load `gdrdrv`:

```bash
cd /tmp/gdrcopy/src/gdrdrv
make clean
HAVE_VM_FLAGS_SET=y make -j
cd /tmp/gdrcopy
sudo ./insmod.sh
ls -l /dev/gdrdrv
```

## Build

```bash
cmake -S . -B build -DBPFTIME_ENABLE_CUDA_ATTACH=ON -DBPFTIME_CUDA_ROOT=/usr/local/cuda-12.9 -DBPFTIME_ENABLE_GDRCOPY=ON
cmake --build build -j --target gpu_array_map_host_perf
```

## Run

The benchmark binary:

- `build/benchmark/gpu/host/gpu_array_map_host_perf`

Example:

```bash
./build/benchmark/gpu/host/gpu_array_map_host_perf --iters 20000 --max-entries 1024 --value-size 8
```

Notes:

- The binary calls `cuInit(0)` explicitly before creating the map (required when no CUDA runtime API has been touched yet).
- You may see a teardown warning `cudaHostUnregister() failed: pointer does not correspond to a registered memory region`. This comes from `bpftime_shm` destructor unconditionally calling `cudaHostUnregister()` even when the segment was never registered (server mode).
- Enable GDRCopy path: `BPFTIME_GPU_ARRAY_GDRCOPY=1` (will fall back automatically if pin/mapping fails).

## Results

All runs use:

- `iters=20000`
- `max_entries=1024`
- keys generated by a simple LCG (pseudo-random access)

### Baseline (cuMemcpy)

### value_size = 8 bytes

- update: `3787.8 ns/op` (`264004 ops/s`)
- lookup: `4732.9 ns/op` (`211286 ops/s`)

### value_size = 64 bytes

- update: `3835.2 ns/op` (`260741 ops/s`)
- lookup: `5048.0 ns/op` (`198098 ops/s`)

### value_size = 256 bytes

- update: `3843.6 ns/op` (`260170 ops/s`)
- lookup: `5024.9 ns/op` (`199007 ops/s`)

### GDRCopy enabled (BPFTIME_GPU_ARRAY_GDRCOPY=1)

On this machine, enabling GDRCopy does **not** improve lookup latency because CUDA reports that GPUDirect RDMA is unsupported:

- `CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED=0`

In that case, bpftime disables GDRCopy for this map and continues using `cuMemcpyDtoH` automatically, so performance stays effectively the same.

Example (8B):

- update: `3808.0 ns/op` (`262608 ops/s`)
- lookup: `4745.2 ns/op` (`210741 ops/s`)

Interpretation:

- In this range (`8B`–`256B`), latency is dominated by per-call CUDA driver overhead (and synchronization), not payload size.
- This is exactly where `gdrcopy` can help for host-side polling workloads by avoiding `cuMemcpyDtoH` in `elem_lookup()`.

## gdrcopy refactor plan (GPU_ARRAY_MAP)

Target implementation:

- `runtime/src/bpf_map/gpu/nv_gpu_shared_array_map.cpp`

### Phase 0: prerequisites and toggles

- Add an optional build flag `BPFTIME_ENABLE_GDRCOPY`.
- Add runtime toggles:
  - `BPFTIME_GPU_ARRAY_GDRCOPY=1` (enable)
  - `BPFTIME_GPU_ARRAY_GDRCOPY_MIN_BYTES=<N>` (only enable when `value_size * max_entries >= N`)
- Runtime checks:
  - `CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED == 1` (otherwise pinning fails and bpftime must fall back)
  - `dlopen("libgdrapi.so")` succeeds
  - `/dev/gdrdrv` exists and is accessible

## How to actually enable GDRCopy on a machine

GDRCopy requires **hardware/driver support for GPUDirect RDMA**. If CUDA reports:

- `CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED=0`

then there is no software-only fix on that system: GDRCopy pinning will not work (this is common on consumer GeForce SKUs).

If you want to double-check (or force a best-effort try anyway), bpftime supports overrides:

- `BPFTIME_GPU_ARRAY_GDRCOPY_FORCE=1` – try GDRCopy even when CUDA reports `RDMA_SUPPORTED=0`
- `BPFTIME_GPU_ARRAY_GDRCOPY_FORCE_PCIE=1` – when `gdr_pin_buffer_v2` is available, try `GDR_PIN_FLAG_FORCE_PCIE`

On this RTX 5090 test machine, even with both overrides, `gdr_pin_buffer` still fails with `EINVAL (22)`, so the system does not support pinning GPU memory for CPU mapping.

On a system where it reports `=1`, the minimal enablement checklist is:

1) Build bpftime with GDRCopy enabled:

```bash
cmake -S . -B build -DBPFTIME_ENABLE_CUDA_ATTACH=ON -DBPFTIME_ENABLE_GDRCOPY=ON
cmake --build build -j
```

2) Install and load GDRCopy (`libgdrapi` + `gdrdrv`):

```bash
git clone https://github.com/NVIDIA/gdrcopy /tmp/gdrcopy
cd /tmp/gdrcopy
make -j CUDA=/usr/local/cuda-12.9 prefix=/usr/local lib_install
sudo ldconfig
cd /tmp/gdrcopy/src/gdrdrv
make clean
HAVE_VM_FLAGS_SET=y make -j
cd /tmp/gdrcopy
sudo ./insmod.sh
ls -l /dev/gdrdrv
```

3) Run with the runtime toggle:

```bash
BPFTIME_GPU_ARRAY_GDRCOPY=1 ./build/benchmark/gpu/host/gpu_array_map_host_perf --iters 20000 --max-entries 1024 --value-size 8
```

4) Confirm it is active:

- `nv_gpu_shared_array_map_impl` logs `gdrcopy enabled for GPU_ARRAY_MAP: ...`


### Phase 1: accelerate host-side `elem_lookup()` only (safe)

Goal: keep correctness risk low by leaving updates as `cuMemcpyHtoD`, but remove the `cuMemcpyDtoH` cost on reads.

- When the device buffer is available (`server_gpu_shared_mem` on server, or `cuIpcOpenMemHandle()` result on agent):
  - `gdr_open()`
  - `gdr_pin_buffer(gdr, (uintptr_t)device_ptr, total_size, 0, 0, &mh)`
  - `gdr_map(gdr, mh, &bar_ptr, total_size)`
  - `gdr_get_info(gdr, mh, &info)` and compute `cpu_ptr = (uint8_t*)bar_ptr + (device_ptr - info.va)`
- In `elem_lookup()`:
  - Replace `cuMemcpyDtoH*` with `gdr_copy_from_mapping(value_buffer.data(), cpu_ptr + key*value_size, value_size)`
  - Keep returning `value_buffer.data()` (preserve current pointer semantics).
- Keep `elem_update()` unchanged (still `cuMemcpyHtoD*`).

Why this phase is attractive:

- Read-mostly workloads (polling counters, sampling state) get the biggest win.
- Avoids subtle “CPU store → GPU load visibility” questions for correctness.

### Phase 2: optional “direct mapped pointer” lookup (zero-copy)

If the project wants `bpf_map_lookup_elem()` on host to behave like “pointer into backing storage” (similar to userspace array map), then:

- Make `elem_lookup()` return `cpu_ptr + key*value_size` directly.

Risks to address:

- Callers can mutate returned memory without calling update; decide whether to allow it (and document) or keep Phase 1 behavior.

### Phase 3: accelerate host-side `elem_update()` (harder)

Only after Phase 1 is stable:

- Replace `cuMemcpyHtoD*` with `gdr_copy_to_mapping(cpu_ptr + key*value_size, value, value_size)`.
- Define/update consistency rules:
  - If host updates are used to set initial state before launching kernels, ensure any required host-side ordering is enforced (likely a `std::atomic_thread_fence(std::memory_order_seq_cst)` plus stream/launch ordering documentation).
  - If kernels and host can race on the same key, define “last writer wins” vs “requires lock/seq”.

### Phase 4: integration + measurement

- Add a second benchmark mode to `gpu_array_map_host_perf`:
  - baseline: current `cuMemcpyDtoH`
  - gdrcopy: `gdr_copy_from_mapping`
- Compare `ns/op` before/after for the same `(iters, value_size, max_entries)` grid and record results in this document.
